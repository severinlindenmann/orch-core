ok describe follow_up
Schedule a fresh session, release your claim, then end this session.
usage: orch follow-up [REF] [--in DURATION] [--at WHEN] [--brief-file PATH] [--brief TEXT] [--label LABEL] [--on-status STATUS] [--on EVENT] [--dry-run]
who: agent · emits: followup.set
args:
  REF  ticket REF (DEMO-0043, 43); default: your claim
  --in DURATION  duration: 90m, 36h or 2d
  --at WHEN  local time: YYYY-MM-DDTHH:MM[:SS] or +2d 09:00
  --brief-file PATH  read the text from PATH, or - for stdin
  --brief TEXT  instructions for the fresh session
  --label LABEL  optional label
  --on-status STATUS  with --on <add-on event>: wake only when the add-on reports this status (default: any status it declared); another status does not wake it early, the deadline does
  --on EVENT  wake on an event instead of a time (--in/--at is then the deadline): question.answered, ticket.changed:testing, gate.approved:plan, webhook:<id from orch webhook new> or an add-on event such as databricks.run.finished:<run id> (the add-on checks it in the background; verify the result)
  --dry-run  say what would happen, append nothing
errors:
  ambiguous_ref (exit 2): name the ticket REF, for example DEMO-0043 | fix: orch status
  not_found (exit 2): orch list
  addon.off (exit 3): tell the person; do not work around it | fix: orch addon list
  followup.bad_brief (exit 3): provide a brief of 1 to 4096 UTF-8 bytes | fix: orch follow-up --help
  followup.denied (exit 3): read the denial code and resolve it before retrying | fix: orch show
  followup.too_far (exit 3): choose a time within 14 days | fix: orch follow-up --help
  followup.too_soon (exit 3): wait inside the session | fix: orch wait
  grant.expired (exit 3): ask the person for a new grant | fix: orch status
  grant.required (exit 3): ask the person to run orch grant, then set ORCH_GRANT | fix: orch status
  sign.cancelled (exit 3): run it again to review | fix: orch help
  tty.required (exit 3): run it in your terminal | fix: orch help
  lock.busy (exit 4 retry): retry in a moment | fix: orch status
  parse.text (exit 6): orch describe follow_up
out: ok {key} followup.set {id} due={due} state={state} / next: {next}
