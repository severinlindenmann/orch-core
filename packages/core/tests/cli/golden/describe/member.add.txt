ok describe member.add
Add a member with a role; their first device certificate comes with the invitation.
usage: orch member add --name NAME [--role owner|maintainer|member|viewer] --pk KEY --cert PATH [--reader-decl PATH] [--dry-run]
who: human · emits: member.added
pre: workspace_exists role_allows user_presence text_clean
args:
  --name NAME  display name (required)
  --role ROLE  role (owner|maintainer|member|viewer) [default member]
  --pk KEY  their public key, b64u (required)
  --cert PATH  their device certificate: PATH or - for stdin (required)
  --reader-decl PATH  their reader declaration: PATH
  --dry-run  say what would happen, append nothing
errors:
  custody.no_key (exit 3): orch setup sets up your device key | fix: orch help
  custody.no_prompt (exit 3): run this command yourself, in your own terminal | fix: orch help
  custody.wrong_passphrase (exit 3): run the command again and type your passphrase | fix: orch help
  human_only (exit 3): orch ask or orch wait | fix: orch describe ask
  reader.decl_invalid (exit 3): make a new one with the reader's own orch (orch keys reader declare) | fix: orch help
  role.denied (exit 3): ask an owner or maintainer | fix: orch status
  sign.convenience_readers (exit 3): pass the reader's declaration (orch keys reader declare --enrol, then --reader-decl PATH) | fix: orch help
  lock.busy (exit 4 retry): retry in a moment | fix: orch status
  parse.json (exit 6): orch describe member.add
  parse.text (exit 6): orch describe member.add
  members.stale (exit 9 retry): retry; the person re-signs | fix: orch status
out: ok member.added {person} {role} seq={seq} / next: {next}
