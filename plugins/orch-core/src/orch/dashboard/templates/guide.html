The idea in three lines

Tickets are Markdown files

Requirements, acceptance criteria, plan, tasks and proof live in orchestrator/tickets/ in your repo, versioned with your code. No server, no account.

Agents do the work

They file tickets, draft requirements, plan, claim, work a task list with evidence and hand over for testing, all through one CLI, orch.

You decide at gates

Four decisions stay with you: the requirements, the plan, the verdict and the close. Everything between them runs without you.

Where a person has to say yes

A gate is a point the agent cannot pass on its own. You see the full text it binds, approve it, and orch signs that decision into a ledger. The agent proceeds only on what the ledger holds.

Signed, not just clicked

Each approval, answer, verdict and close is bound to a hash of the exact text you saw and signed into a per-user ledger (ledger.jsonl, HMAC key in your orch config dir). orch check flags anything the ledger does not hold.

Agents cannot approve

Human commands are refused when any parent process is an agent harness, and a guard hook blocks the spellings it can read. An agent claims, works and moves to testing only on decisions the ledger holds.

Changed text voids the approval

Edit approved requirements or plan and the agent stops. Today shows a re-approval with a diff instead of letting stale consent carry over.

The honest limit: code running as your user outside the guard can read your files, the key included. orch makes shortcuts hard and visible; it is not an OS sandbox. Run agents as a separate user if you need that.

Your day in Mission Control

Five places, one rule: whatever needs a person comes first.

Today

The decisions waiting on you, blocking first. Each card shows the full text it binds and one primary action: answer, approve, or give a verdict against a checklist of criteria and their evidence.

Board

Your move on top, the agents' flow below: Ready, Working, Waiting, Testing. Group by epic, sprint, label, agent or repo. Drag a card to move it; gates still say no.

Activity

Which agents work now, which went silent, and every event, newest first. Same-actor runs fold into one line. Start an agent on a stale ticket from here.

Epics and delegation

Approve an epic once for all its children. Optionally delegate: agents may approve small children they add themselves, up to a limit you sign. Pause any time; verdicts stay yours.

Claims

An agent claims a ticket before touching it, so two agents never work the same one. A claim whose agent goes quiet shows as stale and you can release it.

Reports

Lead time, waiting time and sent-back rate over time: where work waits, and whether it is you.

Addons that meet the work where it is

Off until you enable them per workspace. Custom addons run only after you trust that exact version.

GitHub issues and reviews

Pull requests and their checks next to their tickets, rerun failed runs, import an issue as a ticket, close and reopen in sync.

Terminals

Run, watch and type into agent sessions from the dashboard. Needs tmux.

Ticket usage

What a ticket cost: output tokens per model, an estimate at API list prices and your 5-hour and weekly limits with a pace sentence.

Wiki

Related pages on each ticket, and a hint when a page may need an update. From a GitHub wiki or a Markdown folder.

Answer an agent from your phone

A phone companion addon can pair a phone so you answer a blocked agent, approve or give a verdict from the train. The companion can be end-to-end encrypted, so the server in the middle holds only ciphertext. The decision still passes core's checks (pairing, signature, age, the hash of the exact text it was given for), is applied on your desktop and is signed into the same ledger, marked as made from your phone. The agent just keeps waiting on orch wait. Revoke a phone any time.

What you get as a team lead

Control without babysitting

You are not watching terminals. You are asked four kinds of question, each with the text it decides on.

An audit trail

Who approved which text, when and from where, in a signed ledger and an event log. Answerable months later.

Fewer interruptions

Agents batch their questions with options and a recommended default, then wait. Non-blocking ones wait for you to confirm.

Parallel agents, safely

Claims keep agents apart, epics cover many children with one decision, and nothing ships past a gate unseen.

Get started in three steps

  1. Install the plugin

    claude plugin marketplace add severinlindenmann/orch-core
claude plugin install orch-core@orch-core

  2. Set up your repository

    In the repo, say "set up orch here" or run /orch-core:setup. It asks one question at a time and writes nothing until you say yes.

  3. Open Mission Control

    In your own terminal, never through an agent:

    orch serve

    Ask an agent for a ticket, then approve its requirements on Today.

The full reference is the plugin README in the orch-core repository; this page is the short version.
