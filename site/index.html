Let coding agents do the work. Keep every decision yours.

orch runs agent work through tickets on a fixed path. Agents write the requirements, the plan and the evidence; you sign the requirements, the plan and the verdict, and orch refuses to move on without your signature. It works with Claude Code, Codex and any agent that has a shell.

Everything flows into the core

A request comes in, in the requester’s own words. The agent gets the keys and knowledge it needs, follows your skills and rules, and writes every step into the ticket. People answer questions and sign the gates. The results go back to your tracker, docs, code host and data platform, and every finished ticket adds to what the next one can draw on.

At your desk

Mission Control is a local dashboard. Every prompt that signs something shows you exactly what you sign, and only core can show it, never an addon.

On your phone

orch mobile answers questions and signs gates from an iPhone. One QR scan joins a workspace, and logging out wipes it. Every signature needs Face ID, and the device key stays in the Secure Enclave.

How the pieces fit together

One host per machine holds the keys. Agents talk to it through a narrow socket, and your phone and other workspaces reach it through a relay that only ever sees ciphertext.

orch CLI
Agent-first commands with terse output: new, claim, task, ask, artifact, submit. Any agent with a shell can use it.
Workspace
Plain files: per ticket a ticket.json, body.md, events.jsonl and artifacts/. Every change is an appended, signed event.
Host
orch serve is the only process that loads keys, from the OS keychain or the Secure Enclave. It enforces gates, roles and policies.
Mission Control
The desktop dashboard, itself an addon. Other addons: GitHub reviews and issues, Databricks, wiki, terminals, schedules, quick tasks, or your own, each trusted per version.
orch-relay
Directory, relay, Drop and push. It stores ciphertext only and runs as a public instance or inside your company. orch-relay
orch mobile
The native iPhone app for questions, approvals and verdicts, with push and Drop. orch-mobile
Linked workspaces
Hand a ticket to another workspace (yours, a colleague’s or one on a client’s VM) and continue with the result. Incoming tickets are untrusted until you accept them.

Works with the agent you already use

Every command is defined once, and gates and signatures are enforced by orch itself, not by a hook in one particular agent.

Try the v2 preview

v2 is in development on the develop branch. Core, host, dashboard and relay are merged, and the iPhone app is in TestFlight.

For daily work, use v1 from main.

git clone -b develop https://github.com/severinlindenmann/orch-core.git
uv tool install ./orch-core/plugins/orch-core

cd your-project
orch init           # creates the workspace and writes AGENTS.orch.md
orch host enable    # starts the host as a per-user service
orch help work      # what an agent reads first

You need uv and Python 3.11+. The full design, threat model and phases are in orch-v2.md.

orch is built by Severin Lindenmann, out of two years of trial and error on real projects. It is one approach among several, not the one best practice.
